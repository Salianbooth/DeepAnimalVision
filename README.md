# DeepAnimalVision

> 项目简短描述：基于深度学习实现基于深度学习的动物图像识别与分类系统设计与实现

## 一、项目规划

### 1. 核心目标

- 短期（1-2 周）：完成项目基础框架搭建，实现核心功能的最小可运行版本（MVP）；
- 中期（2-4 周）：完善功能模块，完成单元测试与集成测试，优化性能；
- 长期（4 周 +）：部署上线 / 开源发布，补充文档，修复已知问题，迭代新功能。

### 2. 阶段里程碑

|  阶段  | 时间范围 |             核心任务              |                  交付物                  |
| :----: | :------: | :-------------------------------: | :--------------------------------------: |
| 阶段 1 |  Week 1  |  需求分析、技术选型、项目初始化   | 技术选型文档、项目基础工程、Git 仓库搭建 |
| 阶段 2 | Week 2-3 | 核心模块开发（如检测 / 识别算法） |    可运行的核心功能代码、单元测试用例    |
| 阶段 3 |  Week 4  |   功能整合、性能优化、Bug 修复    |       完整运行的项目、性能测试报告       |
| 阶段 4 | Week 5+  |     文档完善、开源发布 / 部署     | 完整 README、部署文档、线上服务 / 开源包 |

### 3. 技术栈

- 编程语言：Python 3.8+
- 核心框架：PyTorch/TensorFlow（根据项目选）、OpenCV
- 工具链：Git、PyCharm
- 部署环境：Windows/Linux、CUDA 11.7+（可选）

## 二、Git 上传规范要求

### 1. 分支管理规则

- `main`：主分支，仅存放稳定可运行的代码，禁止直接提交，仅通过合并请求（PR）更新；
- `dev`：开发分支，日常开发的核心分支，所有功能分支均从`dev`创建；
- `feature/xxx`：功能分支，如`feature/detection-model`（交通标志检测模型），完成后合并到`dev`；
- `bugfix/xxx`：修复分支，如`bugfix/accuracy-drop`（修复识别准确率下降问题），完成后合并到`dev`。

### 2. 提交信息规范

提交信息格式：`[类型] 描述（不超过50字）`

- 类型可选：`feat`（新功能）、`fix`（修复 Bug）、`docs`（文档更新）、`style`（格式调整，不影响代码逻辑）、`refactor`（重构）、`test`（测试代码）、`chore`（杂项，如依赖更新）；

- 示例：

  

  ```
  [feat] 新增交通标志分类数据集加载模块
  [fix] 修复检测模型推理时的内存泄漏问题
  [docs] 更新README中的Git上传规范
  ```

  

### 3. 上传流程要求

1. 本地开发前，先拉取远程最新代码：`git pull origin dev`；

2. 开发完成后，提交本地修改：

   ```
   git add .  # 添加所有修改文件（或指定文件）
   git commit -m "[feat] 新增xxx功能"  # 按规范写提交信息
   ```

   

3. 推送分支到远程：`git push origin feature/xxx`；

4. 打开 GitHub 仓库，创建 PR（合并请求），将`feature/xxx`合并到`dev`；

5. 审核通过后合并，删除本地 / 远程的功能分支（可选）。

### 4. 其他要求

- 禁止上传大文件（如大于 100MB 的数据集 / 模型），建议用 Git LFS 或单独存储；
- 禁止上传敏感信息（如密钥、个人令牌、隐私数据）；
- 每次提交前确保代码可运行，无语法错误，核心功能测试通过；
- 上传前执行`git status`检查，避免提交无关文件（如`.idea`、`__pycache__`、`.env`）。

## 三、项目部件分类

### 1. 核心功能模块

|   模块名称   |     路径      |                    功能描述                    |
| :----------: | :-----------: | :--------------------------------------------: |
| 数据处理模块 |  `src/data/`  | 数据集加载、预处理（如裁剪、归一化）、数据增强 |
|   模型模块   | `src/models/` |    检测 / 识别模型定义、模型训练 / 推理逻辑    |
|   工具模块   | `src/utils/`  |    通用工具函数（如日志、可视化、文件操作）    |
|   配置模块   |   `config/`   |     项目配置文件（如模型参数、数据集路径）     |

### 2. 辅助模块

| 模块名称 |    路径    |                  功能描述                  |
| :------: | :--------: | :----------------------------------------: |
| 测试模块 |  `tests/`  |           单元测试、集成测试代码           |
| 文档模块 |  `docs/`   |    技术文档、接口文档、部署文档（可选）    |
| 脚本模块 | `scripts/` | 辅助脚本（如数据集下载、模型训练启动脚本） |

### 3. 项目根目录文件说明

- `README.md`：项目总览、规划、规范（当前文件）；
- `requirements.txt`：项目依赖包列表（如`torch==2.0.1`、`opencv-python==4.8.0`）；
- `.gitignore`：Git 忽略文件配置（排除`.idea`、`__pycache__`、`data/raw`等）；
- `main.py`：项目入口文件（如启动实时识别程序）。

## 四、快速开始

### 1. 克隆仓库

```
git clone https://github.com/Salianbooth/RealTime-TSR.git  # 替换为你的仓库地址
cd RealTime-TSR
```

### 2. 安装依赖

```
pip install -r requirements.txt
```

### 3. 运行项目

```
python main.py
```
